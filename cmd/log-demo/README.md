# Log demo

The log demo fills a development Svarog server with generated logs from several
clients and integrations.

## Run

In the Svarog web UI, create clients and paste their connection URLs into
`.env.log-demo`. From the repository root:

```bash
cp .env.log-demo.example .env.log-demo   # then fill in the connection URLs
docker compose -f docker-compose.log-demo.yml up -d --build
```

## Services

| Service                                    | Integration                                                                                             | Default replicas |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ---------------- |
| `demo-api`, `demo-worker`, `demo-payments` | [Generator](main.go) piped into the [CLI client](../client/README.md)                                   | 3, 2, 2          |
| `demo-native`                              | [Go `slog` and `log`](../log-interceptor-demo/main.go) through [`svaroglog`](../../svaroglog/README.md) | 1                |
| `demo-spring-boot`                         | [Spring Boot demo](../../java/svarog-spring-boot-demo) through the [Java starter](../../java/README.md) | 1                |

The CLI generators pick random lines from [messages.txt](messages.txt) at
random levels.

The Spring Boot demo simulates one order per `DEMO_INTERVAL` and replica, with
product names generated by Datafaker. Logs of one order share an `orderId` and
show successful orders, out-of-stock rejections and payment timeouts with one
retry. If both payment attempts time out, the order logs an error with a stack
trace. The demo does not call a real payment service. Compose runs it in Spring
Boot's non-web mode so replicas can share the host network.

## Configuration

Set these variables in `.env.log-demo`.

| Variable                                                                  | Default            | Purpose                                                                                                                       |
| ------------------------------------------------------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `API_CONN_STRING`, `WORKER_CONN_STRING`, `PAYMENTS_CONN_STRING`           | Required           | Connection URLs for the API, worker and payments generators, respectively.                                                    |
| `NATIVE_CONN_STRING`                                                      | `API_CONN_STRING`  | Connection URL for the native Go demo.                                                                                        |
| `SPRING_BOOT_CONN_STRING`                                                 | `API_CONN_STRING`  | Connection URL for the Spring Boot demo.                                                                                      |
| `DEMO_INTERVAL`                                                           | `1s`               | Time between generated records per replica. For fractional seconds, use milliseconds, e.g. `1500ms`.                          |
| `API_REPLICAS`, `WORKER_REPLICAS`, `PAYMENTS_REPLICAS`, `NATIVE_REPLICAS` | `3`, `2`, `2`, `1` | Number of containers for each service, respectively.                                                                          |
| `SPRING_BOOT_REPLICAS`                                                    | `1`                | Number of Spring Boot containers.                                                                                             |
| `DEMO_NETWORK_MODE`                                                       | `host`             | Docker network mode. `host` reaches NATS bound to `127.0.0.1:4222` on Linux; bridge networking is enough for a remote server. |

When running a generator outside the demo Compose file, these variables also
apply:

| Variable             | Default                              | Purpose                                                                                 |
| -------------------- | ------------------------------------ | --------------------------------------------------------------------------------------- |
| `DEMO_APP_NAME`      | `demo` (CLI), `demo-native` (native) | Application name attached to generated logs. The demo Compose file sets it per service. |
| `DEMO_MESSAGES_FILE` | `cmd/log-demo/messages.txt`          | Message source for the CLI generator. The image uses `/app/messages.txt`.               |
